## About This Project

This project performs a comprehensive walk-forward analysis of a proprietary algorithmic trading system. Using broker-generated trade reports, the analysis evaluates profitability, risk-adjusted returns, trade duration patterns, and the statistical distribution of profit/loss outcomes.

The project demonstrates:
- **Financial data cleaning** including magic-number correction and feature extraction from broker comments
- **Distributional analysis** of profit-per-lot using skewness, kurtosis, and fitted probability distributions
- **Monte Carlo simulation** to estimate forward performance under realistic assumptions
- **Risk metrics** including drawdown analysis and consecutive-loss probability

---

## Problem Statement

Algorithmic trading systems require rigorous performance evaluation beyond simple profit/loss accounting. This project addresses:

1. What is the net profitability and risk profile of the trading algorithm over the testing period?
2. What is the statistical distribution of returns, and does it match any known probability distributions?
3. Are there profitable intraday or day-of-week patterns?
4. How does performance vary across instruments (symbols)?
5. What is the probability of experiencing consecutive losses, and what is the maximum drawdown?
6. Using Monte Carlo simulation, what is the expected forward performance over the next 100 trades?

## Methodology

### 1. Data Cleaning & Transformation

The raw broker CSV undergoes extensive cleaning and feature engineering:

| Step | Action | Rationale |
|------|--------|-----------|
| Magic number correction | Changed `12345` â†’ `4444` | Fixed algorithm identifier mismatch |
| Price validation | Count `Open Price <= 0`, `Close Price <= 0` | Ensure valid price data |
| Lot validation | Count `Lots <= 0` | Ensure valid position sizes |
| Symbol cleaning | Strip `+` and `.` from symbol names | Standardize instrument names |
| Datetime conversion | `Open Datetime`, `Close Datetime` â†’ `datetime` | Enable time-based analysis |
| Chronological sort | Sort by `Open Datetime`, reset index | Required for running calculations |
| Time features | Extract `Open Date`, `Open Hour`, `Open Day` | Enable temporal aggregations |
| Duration | `(Close Datetime âˆ’ Open Datetime)` in minutes | Trade holding period |
| Profit | `Profit + Swap + Commission` | Net profit per trade |
| Profit Per Lot | `Profit / (Lots / 0.01)` | Normalize across position sizes |
| Direction | `Buy` if `Type == 0`, else `Sell`; `Direction = 1` or `-1` | Trade side |
| Stop-loss flag | `[[sl]]` in `Comment` | Identify SL-triggered exits |
| Take-profit flag | `[[tp]]` in `Comment` | Identify TP-triggered exits |
| Stops Distance | `%` difference between TP and SL | Risk-reward ratio |
| Column drop | Remove `Ticket`, `Commission`, `Comment`, `Type`, `Take Profit`, `Stop Loss` | Uninformative after extraction |

**Data quality checks passed:**
- No missing values
- `Commission` column is constant (all zeros)
- All prices and lot sizes positive

### 3. Statistical Analysis

**Profit Per Lot distribution characteristics:**
- **Shape:** Positively skewed (right tail from large wins)
- **Kurtosis:** Leptokurtic (fat tails relative to normal)
- **Interpretation:** Consistent with a defined-risk strategy â€” small frequent losses, large infrequent gains

**Distribution fitting:**
- Empirical CDF compared against **power-law** and **exponential** distributions
- Neither distribution perfectly fits the empirical data, though both serve as rough approximations

**Consecutive loss probability:**
- Modeled using geometric distribution with `p = loss_probability / 100`
- Probability of 10 consecutive losses: computed analytically

**Max drawdown:**
- Computed from cumulative profit curve
- Tracked maximum peak-to-trough decline and duration

### 4. Monte Carlo Simulation

To estimate forward performance, a Monte Carlo simulation was conducted:

| Parameter | Value |
|-----------|-------|
| Assumption | Future trades similar to observed dataset |
| Position size | Fixed 0.01 lot |
| Sampling | `Profit Per Lot` with replacement |
| Portfolio per simulation | 100 trades |
| Number of simulations | 100,000 |

**Outputs:**
- Probability of profit over next 100 trades
- 95th percentile (best-case scenario)
- 5th percentile (worst-case scenario)
- Maximum and minimum profit across all simulations
- Full distribution of cumulative returns

## Limitations

- **Small sample size:** 92 trades is insufficient for robust statistical inference; results may not generalize.
- ** Survivorship bias:** Only closed trades are analyzed; open positions and stopped-out strategies are not fully captured.
- **Non-IID returns:** Trade outcomes are likely autocorrelated due to market regime changes, violating independence assumptions in Monte Carlo simulation.
- **Data quality:** Broker-reported data may contain execution errors; magic-number correction suggests data integrity issues.
- **No transaction cost model:** Spreads, slippage, and broker fees are simplified or omitted.
- **Overfitting risk:** The 2pm/4pm pattern may be a spurious discovery from a single month of data.
